# PerceiverCPI-anchored few-shot geometry disagreement: implementation checkpoint

**8 November 2026 | DynaCPI v4 | Hypothesis/engineering result only, no empirical drug–target performance claim**

## Scientific question

Can a *separately frozen geometry-aware* predictor reveal a **query-specific residual improvement** beyond what the **original frozen PerceiverCPI** can achieve after receiving the identical five same-assay, target-specific support measurements?

The previous architecture swap performed worse than original PerceiverCPI on a short exploratory development comparison. The revised design **keeps Perceiver's predictions**, supplies all models with the **same support information**, and tests geometry's marginal contribution. This is deliberately a narrower hypothesis than simply adding ESM, ChemBERTa or GVP features.

## Implemented comparison: six arms, identical task/queries

Module: `dynacpi/perceiver_disagreement_fewshot.py`, function `compare_perceiver_fewshot(...)`.

| Arm | Form / information |
|---|---|
| P0 | Original frozen PerceiverCPI `p0(q)`; no support adaptation |
| P5-global | P0 plus regularized mean support residual |
| P5-local | P0 plus regularized stereo-Morgan Tanimoto^4-weighted support residual |
| P5-KR | P0 plus bounded regularized kernel-ridge support residual |
| D5-no-geometry | Exactly P5-global: calibration-only control |
| **D5-geometry** | P5-global plus bounded, centered disagreement-derived correction |

P5 controls are generated by the existing `dynacpi/perceiver_equal_support_controls.py`. The new module does NOT accept query affinities and does not load any original assay files. It only accepts `PredictionEpisode` with source-task support labels, query chemical identities and two strictly aligned **frozen prediction caches** (Perceiver and candidate geometry predictor).

## Geometry correction and safety constraints

Define `d_i = p_geometry(i) - p_Per(i)`, residual `r_i = y_i - p_Per(i)`, and `k_i = Tanimoto(q,i)^4` for each *support* molecule, then center both `d_i` and `r_i` using only the query-dependent support weights. Denote the weighted disagreement variation `V = sum_i k_i(d_i - dbar)^2`.

The centered, clipped slope is

```
theta = clip[ sum_i k_i (d_i-dbar)(r_i-rbar) / (V*(1+ridge_fraction)),
              -theta_cap, theta_cap ]
```

The query correction uses the centered query disagreement `d_q-dbar` but first limits extrapolation to the maximum observed support disagreement spread. It then scales by `N_eff/K`, where `N_eff = (sum k)^2 / sum k^2`, and clamps the final additive correction to ±0.5 pKd under current prototype settings.

For this first synthetic-only prototype the defaults are `ridge_fraction=0.25`, `min_support=3`, `min_effective_support=1.5`, `min_disagreement_variation=1e-6`, `theta_cap=1` and `delta_cap=0.5`. All these must be frozen **before** any independently approved development experiment. They are not fitted by searching the old inspected inner-DEV.

**Necessary invariants:**

- When K=0, the prediction is exactly P0.
- When geometry is missing, K is too small, effective support is insufficient, or support disagreement is constant, **D5 equals P5-global exactly**.
- When the support residual is only a constant assay shift, the centered geometry slope is zero; a calibration-only win must not be misrepresented as geometry learning.
- Constant shifts in the separate geometry predictor cancel through centering.
- The predicted geometry correction cannot exceed ±0.5 pKd by design; chemical-local reliability suppresses corrections when a query has few effectively similar supports.
- Support permutation and a shared query compound set cannot change the result.
- Missing/extra frozen-score cache IDs, nonfinite predictions, wrong chemical hashes, invalid support labels, and support/query overlap must fail closed.

The output deliberately reports **all six predictions**, effective support, disagreement variation, slope, applied geometry correction, an activation flag and reliability factor. If the geometry branch does not actually help, the experiment will show it; a nonzero correction is not an accuracy gain.

## Testing and interpretation

`tests_v4/perceiver_disagreement_fewshot_test.py` uses only fabricated affinities and fictional protein tasks. It tests output alignment, K=0, K=1/2, missing and constant geometry, constant assay offsets, score cache integrity, support permutation, extrapolation, default activation under informative synthetic support, strict bounds and nonleakage of query outcomes.

A deliberately constructed two-query toy case uses fabricated labels containing a known linear geometry-related residual signal. As an **algebraic sanity check only**, the synthetic RMSEs were P0 **0.5202**, P5-global **0.3811**, P5-local **0.4988**, P5-KR **0.4646**, and D5-geometry **0.3164**. These fake labels are generated by the test author from the intended signal; the result is **not an experimental CPI benchmark, model generalization evidence, or an actual PerceiverCPI victory**. It shows the proposed estimator *can* express a gain under suitable conditions, while null/constant-disagreement and missing-geometry tests ensure no spurious correction when the mechanism cannot be identified.

The earlier baseline-preserving PyTorch residual head remains a separate training-time hypothesis. The module in this checkpoint is a **frozen-prediction, no-training K-shot inference rule**. The existing neural module has not been replaced or trained.

## What must happen before we can say “DynaCPI beats PerceiverCPI”

1. Independent source-level Kd and physical construct adjudication; source-family and protein-homology group disjointness; preregistered split. The real scientific gate is still `BLOCKED_UNAPPROVED_NOT_TRAINING_READY`.
2. Obtain **true frozen PerceiverCPI** query and support predictions and a truly independent frozen geometry-aware model with matched assay output units, no heldout training leakage.
3. Compare all six arms on exactly the same target, five supports, queries, seed/draw grid and frozen chemical features. Measure source-family/component macro RMSE, pooled RMSE, MAE and calibration with family-cluster paired uncertainty.
4. Include a **geometry-shuffled negative control** and sequences-only capacity-matched alternative. Passing the few-shot controls but not geometry ablations is not a geometry contribution.
5. Do not choose a favorable support regularizer, geometry model, target subset or best checkpoint using the reserved-test labels. Keep all K-shot and ablation choices fixed using approved train/inner-validation only.
